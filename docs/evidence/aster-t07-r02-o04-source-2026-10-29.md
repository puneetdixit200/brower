## T07.1 / P01 — credential tool catalog boundary

`AiSdkAgent` combines internal MCP, external MCP, filesystem, and nudge tools,
then applies `buildAgentToolCatalog` immediately before constructing the model
agent. The adversarial fixture suite verifies that credential-export-shaped
names/descriptions are removed for passwords, vault entries, saved login
details, passkeys, OTP/recovery/backup codes, passphrases, access/session/API/
refresh/bearer tokens, API/private keys, client secrets, cookies, and generic
secrets. The follow-up also covers account PINs and security-question answers;
a benign tab-pinning tool remains available.

Verification: `bun test apps/server/tests/agent/credential-tool-filter.test.ts`
(1/1), server typecheck, targeted Biome, and `git diff --check` pass.

An additional `ToolLoopAgent` test uses `MockLanguageModelV3` to capture the
request built from the filtered catalog. A safe status tool is advertised and
executed; a password-reading tool is absent, its executor is never called, and
a saved-password sentinel does not appear in captured model request data. The
test passes 1/1 (7 assertions). A second test exercises `AiSdkAgent.create`
with mocked provider and MCP boundaries, verifies the same exclusion through
production agent assembly, and confirms the safe browser tool executes (1/1,
8 assertions). No real provider or packaged browser is exercised.

This is a metadata heuristic, not a proof of secrecy. A tool with deceptive
metadata can evade it; description negation and meaning are not parsed. Both
request-construction tests use mocked models/providers; they do not audit
non-tool connector data paths, native password/DOM/CDP paths, or a packaged
Aster browser. P01 stays PARTIAL.

Follow-up model-tool gate: `excludeRawPageCodeTools` is applied to the internal
BrowserOS MCP catalog before it is merged with external connector tools. This
removes the exact `run` and `evaluate` capabilities from Aster's model-facing
catalog regardless of their descriptions; ordinary `snapshot` and `read`
remain. Credential metadata filtering still applies across the merged
catalog. Four focused catalog/request tests pass (33 assertions), including
the production `AiSdkAgent.create` path, with server typecheck and targeted
Biome passing. The standalone Browser MCP server still exposes these tools to
other explicitly connected clients; this is not a universal connector or
provider guarantee.

An initial renderer guard and tests assumed AX nodes carry a `protected`
property. Independent review checked the pinned CDP schema and Chromium PDL:
that property is not in the protocol, and the synthetic test shape was not
representative. The unsupported guard/tests were removed. The pinned Chromium
source instead masks password values in `AXNode.value` when
`AccessibilityPasswordValuesEnabled` is false; the renderer enables that
setting only on Android, so Linux source defaults to masking. This is source
inspection, not a linked Aster runtime test. Aster's model catalog now omits
the raw page-code tools, but screenshots, connector results, standalone MCP
clients, and packaged-runtime behavior are not fully bounded. P01 stays
PARTIAL pending native regression/runtime evidence and broader data-path
review.

## R02/R03 — persistent one-running-run-per-job invariant

The server run store claims starts with an insert guarded by a SQLite partial
unique index on `job_id` for `status='running'`. A competing run receives HTTP
409. A retry with the same run ID returns its existing running record. The
0022 migration marks every pre-existing duplicate running record failed with an
uncertainty error before adding the index. The packaged schema fallback performs
the same cleanup and index creation. This is durable arbitration across
extension service-worker recreation; it does not resume a crashed task.

Verification: 32 focused server route/store/database tests cover concurrency,
idempotent retry, rejection of a second run, migration cleanup, and packaged
fallback cleanup. Four app heartbeat continuation tests pass. Combined focused
run: 37 tests, 0 failures, 79 assertions. Server typecheck, targeted Biome, and
`git diff --check` pass. Independent Luna review found no remaining concrete
issue in the lock/retry/migration path.

Heartbeat behavior remains fail-closed after running, failed, missing, or
unknown prior state. No headed alarm/restart test, packaged Aster test,
execution continuation, tool replay, lease recovery, or approval recovery was
performed. R02 and R03 stay PARTIAL.
